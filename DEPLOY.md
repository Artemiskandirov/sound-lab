# Выложить на GitHub Pages

Да, просто статикой. Ничего собирать не нужно — тут нет сборщика, зависимостей
и серверного кода, только HTML, JS, CSS и файлы.

## Как

```bash
cd cuelab-production-v13
git init -b main
git add .
git commit -m "CueLab v13.4"
git remote add origin git@github.com:ВАШ_ЛОГИН/ИМЯ_РЕПО.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: Deploy from a branch**,
ветка `main`, папка `/ (root)`. Через минуту сайт будет на
`https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПО/`.

## Что уже учтено

**Все пути относительные.** Pages отдаёт сайт из подпапки
`/ИМЯ_РЕПО/`, а не из корня домена — на этом обычно и ломаются проекты. Здесь
проверено: сайт поднят по адресу с префиксом, все 94 звука декодировались, все
ссылки выгрузки вернули 200, ноль неудачных запросов.

**`.nojekyll` лежит в корне.** По умолчанию Pages прогоняет сайт через Jekyll,
а он молча выбрасывает файлы и папки, начинающиеся с подчёркивания. Сейчас
таких нет, но если добавите — без этого файла они просто исчезнут с сайта.
Заодно деплой быстрее.

**Размеры в пределах лимитов.** 32 МБ и 2176 файлов при лимите Pages в 1 ГБ на
сайт; самый большой файл — 3 МБ при потолке в 100 МБ. Трафик Pages мягко
ограничен 100 ГБ в месяц.

**HTTPS обязателен, и он там есть.** Копирование паттернов в буфер использует
`navigator.clipboard`, который работает только в защищённом контексте — на
`http://` кнопки копирования отвалились бы. На Pages всё по HTTPS.

## Если хотите полегче

Папка `export/` занимает 27 МБ из 32 — это мастера FLAC, сборки под iOS и
Android. Для просто послушать она не нужна:

```bash
echo "export/" >> .gitignore
```

Останется около 5 МБ. Но тогда в интерфейсе перестанут работать кнопки
выгрузки — они ведут прямо в `export/`.

## Про хаптики на Pages

Работать будут ровно так же, как локально: `navigator.vibrate` от хостинга не
зависит. Напомню главное — **в Safari на iOS его нет ни в одной версии**, и все
браузеры на iPhone используют WebKit. Стенд в карточке «Хаптик в браузере»
покажет, что именно доступно на конкретном устройстве.

## Альтернативы

Точно так же лягут на Vercel, Netlify, Cloudflare Pages или любой S3 — это
обычная статика. `vercel.json` в корне уже настроен: длинный кэш на `audio/`.
Для Pages он не нужен и просто игнорируется.
