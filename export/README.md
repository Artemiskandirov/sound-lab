# CueLab — выгрузка

94 звуков, 293 вариантов. Каждая платформа получает своё, потому что
возможности у них разные, и одинаковый файл для всех обедняет самую сильную.

| | звук | хаптик | амплитуда | резкость |
|---|---|---|---|---|
| **web** | Opus + AAC | `cuelab-haptics.js` | нет | нет |
| **ios** | AAC (m4a) | AHAP | да | да |
| **android** | Ogg в `res/raw` | `VibrationEffect` | да | нет |

## Почему хаптики разные

**У веба нет амплитуды.** Vibration API умеет только чередование «вибрирует /
пауза» в миллисекундах, поэтому силу приходится кодировать длиной импульса.
Плюс браузер обрезает паттерны длиннее примерно десяти элементов — веб-версия
уложена в девять и несёт до пяти самых значимых событий.

**У iOS и Android амплитуда есть.** Core Haptics принимает десятки событий,
каждое со своими `HapticIntensity` и `HapticSharpness`. `VibrationEffect`
задаёт амплитуду 0..255 на каждый отрезок. Поэтому нативные выгрузки несут все
события звука (до 48) с настоящей силой, а не с её имитацией.

## Откуда берутся значения

Ничего не проставлено руками. Всё выведено из формы волны:

- **время** — атаки по спектральному потоку с адаптивным порогом;
- **сила** — превышение потока над локальным фоном;
- **резкость** — спектральный центроид в момент атаки. Удар по металлу
  ощущается острее удара по дереву, и это измеримо: у лог-драма 0.06,
  у дерева 0.21, у камня 0.31, у металла 0.35, у стекла 0.44, у тика
  прокрутки 0.80.

Замер по всей библиотеке: 94 из 94 звуков — каждый импульс попадает в реальную
атаку ближе 55 мс, средняя ошибка 0.1 мс.

## Что в папках

```
masters/     FLAC 48 кГц 16 бит — без потерь, вдвое компактнее WAV
web/         Opus + AAC, JS-модуль, манифест
ios/         m4a, AHAP, CueLabHaptics.swift
android/     res/raw/*.ogg, assets/haptics.json, CueLabHaptics.kt
MANIFEST.json
```

Мастера во FLAC нужны, если захотите пережать под свои требования или отдать
звукорежиссёру. Всё остальное собрано из них.
