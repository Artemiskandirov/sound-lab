# CueLab — Android

## Установка

1. `res/raw/` — звуки, имена уже без дефисов.
2. `assets/haptics.json` — паттерны вибро.
3. `CueLabHaptics.kt` — в исходники.

```kotlin
val cue = CueLab(context)
cue.play("tap")
```

## Три пути, от лучшего к запасному

Выбор делается по возможностям мотора, а не по версии Android.

**1. `VibrationEffect.Composition` (API 30+)** — 549 примитивов по
библиотеке, по одному на атаку. Примитив отрабатывается мотором с собственной
огибающей и ощущается чище прямоугольного импульса. Тип выбран по
спектральному центроиду атаки: `PRIMITIVE_TICK` для звонкого,
`PRIMITIVE_CLICK` для среднего, `PRIMITIVE_THUD` для глухого. Перед
использованием обязателен `areAllPrimitivesSupported()` — поддержка у
производителей разная, и на устройстве без нужного примитива композиция просто
не сыграет.

**2. `createWaveform(timings, amplitudes, -1)`** — 1955 отрезков по
библиотеке, амплитуда 0..255 с шагом 16 мс по огибающей громкости
(взвешенной кривой A). Соседние равные отрезки слиты, поэтому массив короче, а
форма та же.

**3. `createWaveform(timings, -1)`** — на моторах без
`hasAmplitudeControl()` остаётся только ритм.

## Про usage

`USAGE_ASSISTANCE_SONIFICATION`: хаптик интерфейса — это отклик на действие
пользователя, а не уведомление. С usage уведомления его заглушит режим
«не беспокоить», и вибро пропадёт там, где оно нужнее всего.

## Формат haptics.json

```json
{
 "tap": {
  "timings": [16, 32, 16],
  "amplitudes": [255, 180, 90],
  "repeat": -1,
  "composition": [{ "primitive": "CLICK", "scale": 0.94, "delayMs": 0 }],
  "stepMs": 16,
  "variants": 6
 }
}
```
